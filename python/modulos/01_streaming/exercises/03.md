# Ejercicio 3: Proxy de Streaming con Cancelación

## 🎯 Objetivo
Construir un proxy que reciba tokens de un productor lento, los reenvíe a múltiples consumidores y permita cancelar el flujo.

## 📋 Descripción
Diseña tres piezas: un productor, un proxy y al menos dos consumidores. El productor debe generar tokens con demora. El proxy debe reenviar cada token a dos colas distintas. Uno de los consumidores debe ser más lento para que se note el efecto del buffering y otro debe poder disparar una cancelación usando `threading.Event`.

El objetivo no es crear una red real, sino entender cómo fluye la presión entre etapas de un pipeline de streaming.

## 💡 Pistas
- `queue.Queue(maxsize=2)` ayuda a visualizar backpressure.
- `threading.Event()` es útil para cancelación cooperativa.
- Usa un sentinel (`END = object()`) para marcar fin de stream.
- Imprime qué consumidor recibió cada token y cuándo pidió cancelar.

## ✅ Criterios de Éxito
- Hay productor, proxy y múltiples consumidores.
- El proxy reenvía tokens a más de un destino.
- La cancelación detiene el pipeline de forma ordenada.
- La salida explica claramente qué está ocurriendo.

## 🚀 Bonus
Mide cuántos tokens procesó cada consumidor antes de la cancelación y muestra un mini resumen final.
