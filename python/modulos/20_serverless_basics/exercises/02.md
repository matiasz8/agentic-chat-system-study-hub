# Ejercicio 02 – Intermedio: Idempotencia con registro de eventos

## Objetivo

Implementar un handler idempotente que detecte eventos duplicados y
los procese solo una vez, aunque lleguen múltiples veces.

---

## Descripción

En sistemas distribuidos, el mismo evento puede llegar más de una vez
(reintentos del bus de mensajes). El handler debe ser idempotente:

```
Evento A (primera vez)  → procesar → guardar ID → responder OK
Evento A (segunda vez)  → detectar ID ya visto → responder OK sin procesar
Evento A (tercera vez)  → detectar ID ya visto → responder OK sin procesar
```

---

## Requisitos

1. Función `generar_id_evento(evento) -> str` que genere un hash SHA-256
   del contenido del evento (usando `hashlib` + `json`).
2. Set global `_eventos_procesados` para registrar IDs ya vistos.
3. Función `handler_idempotente(evento) -> dict` que:
   - Genere el ID del evento.
   - Retorne inmediatamente si el ID ya fue procesado.
   - Procese el evento y registre el ID si es nuevo.
   - Incluya `"idempotente": True/False` en la respuesta.
4. Probar con 4 eventos: 2 únicos y 2 duplicados.

---

## Pistas

- `hashlib.sha256(texto.encode()).hexdigest()[:16]` genera un hash corto.
- `json.dumps(evento, sort_keys=True)` serializa el dict de forma determinista.

---

## Criterios de éxito

- [ ] El mismo evento procesado dos veces devuelve `"idempotente": True` la segunda vez.
- [ ] Eventos distintos se procesan independientemente.
- [ ] El código es ejecutable con `python3 solutions/02.py`.
