# Ejercicio 3: GovernanceEngine con límites

## 🎯 Objetivo

Implementar una capa de gobernanza que combine políticas y rate limiting por agente.

## 📋 Descripción

Construye un `GovernanceEngine` que, antes de ejecutar una tool, valide:

1. si el agente tiene permiso para usarla;
2. si no superó su cuota de invocaciones;
3. si la decisión quedó registrada en auditoría.

Después, ejecuta una simulación con permisos válidos, una denegación por política y otra por rate limit.

## 💡 Pistas

- Un `dict[str, set[str]]` sirve para mapear herramientas permitidas.
- `collections.deque` ayuda a implementar ventanas de tiempo.
- Considera separar `AuditTrail`, `RateLimiter` y `GovernanceEngine`.

## ✅ Criterios de Éxito

- Una tool permitida se ejecuta correctamente.
- Una tool no permitida se bloquea.
- Un exceso de llamadas dispara la denegación por cuota.
- El programa muestra un historial de decisiones.

## 🚀 Bonus

Genera alertas cuando un agente acumule varias denegaciones seguidas.
