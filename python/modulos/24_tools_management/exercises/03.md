# Ejercicio 3: ToolExecutor robusto

## 🎯 Objetivo

Construir un ejecutor de tools con timeout, retries y logging.

## 📋 Descripción

Implementa un `ToolExecutor` que:

1. reciba una definición de tool;
2. ejecute con timeout;
3. capture excepciones;
4. reintente si el error es transitorio;
5. registre cada intento en un log estructurado.

## 💡 Pistas

- `concurrent.futures.ThreadPoolExecutor` sirve para timeout simple.
- Define una excepción `TransientToolError` para distinguir fallos reintentables.
- Guarda cada intento con estado `ok`, `error`, `timeout` o `retry`.

## ✅ Criterios de Éxito

- Una tool lenta genera timeout.
- Una tool transitoria se reintenta y eventualmente puede recuperarse.
- El executor nunca cae sin registrar el incidente.
- El programa muestra el historial de intentos.

## 🚀 Bonus

Agrega versionado de tools y una política para elegir la versión activa.
