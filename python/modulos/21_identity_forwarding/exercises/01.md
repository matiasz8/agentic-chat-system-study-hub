# Ejercicio 01 – Básico: Propagación de token entre servicios

## Objetivo

Implementar un pipeline de 3 capas (API Gateway → Agente → BD) donde el
token de identidad del usuario se propaga automáticamente de capa en capa.

---

## Descripción

En Identity Forwarding, el token no se usa solo para autenticar al usuario
en la puerta de entrada: se propaga a **cada** servicio downstream para que
puedan aplicar sus propias políticas y dejar trazabilidad.

```
Frontend
  │ Authorization: Bearer <token>
  ▼
API Gateway  → valida token → extrae identidad
  │ pasa identidad al agente
  ▼
Agente       → usa identidad para personalizar
  │ pasa usuario_id a la BD
  ▼
Base de Datos → filtra datos según usuario_id
```

---

## Requisitos

1. Función `decodificar_token(token) -> dict` que extraiga el payload
   (puede ser un dict JSON codificado en base64 o simplemente parseado).
2. Función `api_gateway(solicitud) -> dict` que:
   - Lea el header `"Authorization"`.
   - Decodifique el token y extraiga `usuario_id` y `permisos`.
   - Llame al agente con la identidad.
3. Función `agente(solicitud, identidad) -> dict` que verifique si
   `solicitud["accion"]` está en `identidad["permisos"]`.
4. Demostrar 3 casos: acceso permitido, acceso denegado, sin token.

---

## Pistas

- Puedes simplificar el token como un dict serializado en base64.
- `base64.b64decode(payload).decode()` decodifica el payload.

---

## Criterios de éxito

- [ ] Acceso permitido devuelve `statusCode=200`.
- [ ] Acceso denegado devuelve `statusCode=403`.
- [ ] Sin token devuelve `statusCode=401`.
- [ ] El código es ejecutable con `python3 solutions/01.py`.
