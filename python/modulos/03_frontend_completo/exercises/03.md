# Ejercicio 3: Turn Manager con State Machine

## 🎯 Objetivo
Diseñar un manejador de turnos que coordine streaming, tool calls y recuperación de errores mediante una máquina de estados.

## 📋 Descripción
Implementa un flujo con estados como `idle`, `thinking`, `tool_call`, `streaming` y `error`. El manager debe recibir un mensaje del usuario, decidir si necesita herramienta, ejecutar la herramienta, streamear la respuesta final y recuperar el turno si ocurre un fallo transitorio.

La meta es representar explícitamente el ciclo completo del frontend moderno de IA, no solo imprimir un texto final.

## 💡 Pistas
- `Enum` ayuda a representar estados de forma clara.
- Usa un retry limitado para fallos temporales.
- Mantén historial de mensajes para poder re-renderizar la conversación.
- Simula streaming con `time.sleep()` y un loop por tokens.

## ✅ Criterios de Éxito
- El turno pasa por estados bien definidos.
- El manager puede llamar herramientas.
- Existe una estrategia de retry o fallback.
- La salida permite entender el flujo completo del turno.

## 🚀 Bonus
Agrega optimistic UI: inserta un placeholder del asistente antes de recibir la respuesta final y luego actualízalo.
