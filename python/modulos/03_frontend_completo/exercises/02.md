# Ejercicio 2: Dispatcher de Herramientas

## 🎯 Objetivo
Implementar un despachador que registre handlers por nombre y ejecute tool calls devolviendo resultados estructurados.

## 📋 Descripción
Crea una clase o función `dispatch_tool(name, payload)` que consulte un registro de herramientas disponibles. Si el handler existe, ejecútalo y devuelve un diccionario con al menos `tool`, `status` y `result`. Si no existe, responde con un error controlado.

Este patrón es la base del ciclo "agente decide herramienta → herramienta responde → agente compone mensaje final".

## 💡 Pistas
- Un diccionario `{"weather": tool_weather}` es suficiente como registro.
- Usa funciones normales como handlers.
- Captura errores para no romper toda la sesión.
- Mantén el contrato de salida consistente.

## ✅ Criterios de Éxito
- Se pueden registrar y ejecutar herramientas por nombre.
- Las respuestas son estructuradas.
- Los errores se manejan sin crash.
- Hay una demo completa dentro de `main()`.

## 🚀 Bonus
Agrega validación simple del payload y un campo `duration_ms` medido con `time.perf_counter()`.
