# E2E Testing

> E2E Testing
Caso completo: pregunta → respuesta.

End-to-End Testing: Validar el flujo completo de principio a fin.

---

## 🎯 Objetivo

Tests que validen:
- ✅ Input del usuario → Output correcto
- ✅ Flujo completo sin mock (o mock mínimo)
- ✅ Integración entre todas las capas
- ✅ El agente "realmente" funciona

---

## 🔄 E2E vs Unit Testing

| Aspecto | Unit | E2E |
|--------|------|-----|
| **Alcance** | 1 función | Flujo completo |
| **Dependencias** | Mockeadas | Reales (o casi) |
| **Tiempo** | < 100ms | > 1s |
| **Confiabilidad** | Alta | Media |
| **Útil para** | Desarrollo | Verificar que funciona todo |

## 🧪 Estructura de E2E Test

```python
def test_e2e_ask_sage_workflow():
    """
    E2E: Usuario pregunta stock → 
    Agent consulta DB → 
    Devuelve respuesta JSON
    """
    # Setup: Workflow completo con componentes reales
    workflow = CompleteWorkflow()
    
    # Input: Lo que haría un usuario
    user_input = "¿Cuál es el stock del Paracetamol?"
    
    # Action: Ejecutar flujo completo
    result = workflow.run(user_input)
    
    # Assert: Validar resultado
    assert result["status"] == "success"
    assert "stock" in result
    assert isinstance(result["stock"], int)
```

## 5️⃣ Categorías de E2E Tests

### 1. Happy Path (El caso feliz)
```python
def test_e2e_happy_path():
    """Usuario pregunta algo válido → obtiene respuesta válida"""
    result = workflow.run("¿Stock de Paracetamol?")
    assert result["status"] == "success"
    assert result["data"] is not None
```

### 2. Invalid Input (Input inválido)
```python
def test_e2e_invalid_input():
    """Usuario pregunta algo ambiguo → error graceful"""
    result = workflow.run("¿Qué?")
    assert result["status"] == "error" or "clarify" in result
```

### 3. Missing Data (Dato falta)
```python
def test_e2e_missing_data():
    """Medicamento no existe → error claro"""
    result = workflow.run("¿Stock de MedicamentoInexistente123?")
    assert "not found" in result.lower() or "error" in result.lower()
```

### 4. Security (Inyección)
```python
def test_e2e_security():
    """SQL injection attempt → bloqueado"""
    malicious = "'; DROP TABLE --"
    result = workflow.run(f"¿Stock de {malicious}?")
    # Debería fallar o ignorar la inyección
    assert result["status"] == "error" or "DROP" not in str(result)
```

### 5. Performance (Velocidad)
```python
def test_e2e_performance():
    """Workflow responde rápido (< 2s)"""
    import time
    start = time.time()
    result = workflow.run("¿Stock?")
    elapsed = time.time() - start
    assert elapsed < 2.0, f"Took {elapsed}s, should be < 2s"
```

## 🛠️ Fixtures para E2E

```python
@pytest.fixture
def complete_workflow():
    """Workflow con todos los componentes"""
    return CompleteWorkflow(
        llm=MockAnthropic(),
        database=MockDatabase(),
        validator=OutputValidator()
    )

@pytest.fixture
def sample_inputs():
    """Inputs de test"""
    return [
        ("¿Stock de Paracetamol?", "success"),
        ("¿Qué?", "error"),
        (""; DROP TABLE --", "error"),
    ]
```

## 📊 E2E Test Suite Recomendada

| Test | Propósito | Crítico? |
|------|----------|----------|

| Missing data | Completitud | ✅ SÍ |
