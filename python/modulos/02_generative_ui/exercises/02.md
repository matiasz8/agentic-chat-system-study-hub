# Ejercicio 02 – Intermedio: Payload estructurado y validación

## Objetivo

Crear una clase `PayloadUI` que valide los datos del agente antes de
enviarlos al frontend, asegurando que los campos requeridos existen
y tienen el tipo correcto.

---

## Descripción

Antes de renderizar un componente, el backend debe validar que el payload
del agente cumple con el contrato del componente.

En TypeScript se usaría `zod`:
```typescript
const chartSchema = z.object({
  titulo: z.string(),
  valores: z.array(z.number()),
});
const data = chartSchema.parse(agentOutput);
```

---

## Requisitos

1. Definir un diccionario `ESQUEMAS` con al menos 2 tipos de componente,
   especificando campos requeridos y tipos esperados.
2. Implementar `validar_payload(tipo, datos) → list[str]` que devuelva
   la lista de errores encontrados (vacía si es válido).
3. La clase `PayloadUI` debe:
   - Llamar a `validar_payload` en `__init__` (o `__post_init__` con dataclass).
   - Exponer un atributo `valido: bool` y `errores: list[str]`.
4. Demostrar un payload válido y uno inválido (campo faltante o tipo incorrecto).

---

## Pistas

- `isinstance(valor, (int, float))` acepta ambos tipos numéricos.
- Puedes usar `@dataclass` con `field(init=False)` para atributos calculados.

---

## Criterios de éxito

- [ ] Payload válido → `valido=True`, `errores=[]`.
- [ ] Campo faltante → `valido=False`, lista de errores no vacía.
- [ ] Tipo incorrecto → mensaje de error descriptivo.
- [ ] El código es ejecutable con `python3 solutions/02.py`.
